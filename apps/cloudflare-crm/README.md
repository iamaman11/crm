# CRM — простой тестовый пилот на Cloudflare

Один Worker обслуживает React 19 + Vite и API. Данные — в одной D1.

Клиенты, контакты, сделки и задачи: создание, просмотр, редактирование, поиск и удаление. Все данные тестовые. Вход — существующий Cloudflare Access, при первом человеческом входе создаётся пустое рабочее пространство.

- API: `worker/index.mjs`
- UI: `web/src/main.jsx`, `web/src/styles.css`
- D1: `migrations/0001_initial.sql`
- Cloudflare: `wrangler.jsonc`
- Тесты: `npm test`, UI-сборка: `npm run build`

GitHub Actions доверенной ветки публикует Worker + Static Assets и применяет D1-миграцию. https://crm-dev.crm-5bd5e1e1.workers.dev

Усиленная защита и дополнительные инфраструктурные механизмы — после реального production.

После публикации GitHub Actions запускает реальный Chromium на опубликованном URL: клиент → контакт → сделка → задача → обновление страницы → поиск → правки → мобильный экран → удаление. Технический вход используется только для пилотного E2E.

Технические входы `crm-e2e-a` и `crm-e2e-b` имеют разные рабочие пространства. Браузерная приёмка проверяет, что пользователь видит и изменяет свои записи, но не записи другого пользователя.

В разделе «Сделки» есть переключатель «Таблица / Воронка». Воронка показывает пять этапов, число и сумму сделок по каждому этапу. Этап можно поменять прямо на карточке без открытия формы; изменение сохраняется в D1 и переживает обновление страницы. На телефоне колонки идут вертикально.

## Быстрые исправления и диагностика для разработчика

Единый каталог `shared/catalog.mjs` задаёт поля четырёх модулей для UI и Worker API. `npm run locate -- deals` (или `contacts`, `tasks`, `INVALID_INPUT`) без сети выводит JSON с ответственными файлами: конфигурация, интерфейс, API, валидация, миграция, unit-тесты, браузерная приёмка. `npm run doctor` проверяет локальную D1-схему и соответствие полей каталогу, не изменяя данные. В CI он запускается до тестов и сборки.

Авторизованный `GET /api/doctor` на опубликованном приложении проверяет наличие таблиц одним read-only запросом D1 и возвращает SHA, список модулей, состояние БД. Ошибки API имеют `x-crm-error-code` и `x-request-id`: эти же поля и фактическая длительность обработки в миллисекундах записываются в логи Worker. При ошибке интерфейс показывает код и идентификатор запроса.

Новых сервисов, новых таблиц и отдельной админ-панели нет. Локальное измерение `duration_ms` не включает запуск npm/Node и сетевые задержки; для GitHub/Cloudflare и полного Chromium E2E гарантировать миллисекунды невозможно.

## Постоянный контракт масштабирования

Для каждого нового сеанса ChatGPT и каждого кодового изменения действует [AGENTS.md](AGENTS.md). Он закрепляет исключительно чат → GitHub → GitHub Actions → Cloudflare, сохранение экспертной сложности CRM внутри самостоятельных модулей, точную принадлежность коду/тестам и обязательный цикл доказательной приёмки. `shared/catalog.mjs:implementationOwners/ownerFiles` позволяют `npm run locate` находить конкретный владеющий модуль по мере роста проекта; `npm run doctor` предотвращает появление новых функций без объявленного источника и тестов. Первые четыре модуля используют общий код пилота; новые экспертные функции должны иметь собственное расположение. Полная архитектура остаётся одним Worker и D1, пока дополнительная инфраструктура не обоснована измеримой необходимостью.

## Customer 360 — полезная карточка и первая независимая композиция

В «Клиенты» кнопка «Карточка» показывает контакты, сделки, задачи, просрочку и итоговую сумму по одному клиенту. Код read-only композиции находится в `features/customer360/query.mjs`, её UI — `web/src/Customer360.jsx`. Исходные данные остаются в четырёх существующих D1-таблицах, всё tenant-scoped. `GET /api/customer360/:id` требует Cloudflare Access, неизвестный и чужой ID → 404. Вывод ограничен 100 записями каждой категории, точные общие счётчики считаются отдельно, неполные производные метрики обозначены «—». Команды `npm run locate -- customer360` и `npm run doctor` показывают владельца модуля и подтверждают read-only контракт без фиктивной таблицы. Изменение связанных записей — через существующий CRUD. Приёмка — Chromium desktop/mobile + A/B изоляция + unit-тесты.
