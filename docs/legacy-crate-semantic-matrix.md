## Как читать вывод

**Это полная поимённая source-operation и продуктовая сортировка 93/93 crates, НЕ утверждение о функциональной паритетности 93/93 с D1.** Структурное покрытие и все прямые Cargo dependencies проверены по pinned SHA; public declarations и тестовые названия извлечены из каждого вложенного `.rs` файла. Конкретные ветвления, юридическая корректность и эквивалентность ошибок без исполнения исходных тестов и новых D1/browser сценариев не доказаны. Ни один статус `A?`/`D?` не разрешает удалять старый код: это гипотеза, требующая перечисленных proof gates. `B-LATER`/`B-END` означает сохранить нужное поведение как справочный источник, **не переносить сейчас**.

**Оценка ценности:** NOW = немедленная работа над обычной тестовой CRM, NEXT = полезная узкая функция при показанной пользовательской потребности, LATER = сложная функциональность при наличии реального потребителя, END = после MVP/реальных данных/юридических требований, RETIRE-REVIEW = legacy-инфраструктура вне текущего runtime, не воссоздавать. **Безопасность уже работающих операций** (tenant, signed Access, policy, CAS, replay, audit, privacy redaction) остаётся обязательной в любом статусе.

## Приёмка семантического покрытия и переноса

- **Source inventory DONE:** 93/93 каталогов `Cargo.toml`, 532/532 файлов `src/` и `tests/`, поимённые nested entrypoints, public symbols, тестовые функции/названия, строки и прямые исторические зависимости; статический индекс приложен отдельно. `build.rs` и example рассмотрены. Нет утраченных `src/`/`tests/` файлов в срезе.
- **Product triage DONE для 93/93:** каждому crate назначена бизнес-область, класс NOW/NEXT/LATER/END или инфраструктурное RETIRE-REVIEW; условие возможного переноса и владелец. Внутри mixed crate операции/валидаторы читаются отдельно по operation-evidence, один verdict на crate не разрешает массовую очистку.
- **Semantic parity / deletion gate OPEN:** для каждой операции, прежде чем утверждать `A`, провести точную цепочку исходное правило/вход/отказ/тест → существующий owner → Protobuf descriptors → handler/explicit policy → D1 state/receipt/audit → React/native workerd + применимый live proof. `B` закрывается только при фактической реализации; `C` требует явного продуктового исключения; `D` — ноль живых потребителей и доказанный перенос инвариантов. Полного signed-human positive live privacy Gate B всё ещё нет; не маскировать service principal человеком.
- **Нельзя объявлять #352 закрытым** по завершению этого текстового инвентаря. Не строить новый registry/generator/worker/runtime, не возвращать PostgreSQL/SQLx, не вводить custom field/workflow platform. Все будущие доказательства выполняются существующим CI; документация не является исполняемым контрактом.
