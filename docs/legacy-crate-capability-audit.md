# #352 / P0: inventory of all 93 historical Rust crates

**Canonical source snapshot:** [`dev@40f21684393d`](https://github.com/iamaman11/crm/commit/40f21684393d14fe32a3e0d88180e0cd9e70043f) on 21 November 2026; all evidence links below are pinned to this commit.

**Purpose:** preserve real business operations without recreating the old PostgreSQL/SQLx/process architecture. The 5 active shared crates (`crm-core-contracts`, `crm-module-sdk`, `crm-proto-contracts`, `crm-sales-activities-link-contract-adapter`, `crm-customer-360-query-adapter`) are **not** included in this 93-crate inventory. Original pure owners in `modules/*` are also not listed as legacy crates.

**Meaning of evidence:** file/module names and public symbols are *code inventory*, not proof that each operation is accessible via published CRM. A missing linked Rust crate is an early boundary, but an overlapping operation may already be implemented by an original domain owner in the active Worker. No legacy code is safe to delete on the basis of the crate name or absence from Cargo workspace alone.

**Acceptance baseline:** [CI and deploy #44905350282](https://github.com/iamaman11/crm/actions/runs/44905350282) proves 14 linked modules, 64 registered/executed current RPCs, 20 D1 migrations, workerd/Chromium and independent live D1/Traces checks. It does **not** establish behavioral parity for all historical capabilities.

**P0 status:** 93/93 entries structurally enumerated below; operational parity / ownership / exact deletion decisions require evidence. Candidate `B?` means keep original logic for a feature decision or port, `D?` means infrastructure candidate that must be examined for hidden business invariants. Neither is approval to delete.

**Explicit policy:** Protobuf is still the only wire schema; `module.yaml` only declares the owner and method. Historical `crm-core-data`, SQLx `PostgresDataStore`, process-runner, old query engine and `v1` variants are *not* a reason to create runtime adapters or backwards-compatibility paths. The current Worker is D1-only. Use original pure domain owners and preserve the **behavioral invariant**, not the old transport.

**Evidence levels:** `ACTIVE` = active compiled RPC and successful workerd/Cloudflare scenario; `PARTIAL` = some user-visible analogue works but the full historical workflow does not; `SOURCE-ONLY` = historical symbol is present but its crate is not linked; `NOT IMPLEMENTED` = no corresponding active published RPC/worker implementation proven. Decisions A/B/C/D are **not final** when marked with `?`.

**Still needed for P0 DONE:** complete nested-`pub use` expansion, source-level call-site and transitively dependent crate audit for each operation, mapping of each legacy invariant/negative test to a current owner/policy/D1/React/live scenario, and reviewed A/B/C/D with per-operation decisions. The 93/93 root source index is real; it is not 93/93 behavioral parity. Source-only implementation is kept until that gate is met.
